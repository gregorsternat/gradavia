# Requested feature coverage

This is the disposition of the 80 requested capabilities for the expanded
exploration change, reviewed against the implementation on 2026-10-05. It is a
scope record, not evidence of production deployment. See [quality](quality.md)
for verification, [analysis methodology](analysis-methodology.md) for calculations,
[data contract](data-contract.md) for populations, and [external enrichment
feasibility](enrichment-feasibility.md) for reviewed external sources and joins.

- **Delivered**: the requested capability exists within the stated source scope.
- **Bounded**: a useful implementation exists, with a narrower scope explicitly
  described below. This does not mean the entire original request is complete.
- **Deferred**: the capability is not implemented. A source, methodology or
  execution contract still needs work; its absence is not disguised by a mock.

All atlas populations are complete snapshots of one family, campaign and retained
release, capped at 30,000 records with explicit failure above the limit. Missing,
suppressed and invalid values remain distinct from observed zero. APB,
Parcoursup and apprenticeship are separate populations. A source record match is
not proof of an unchanged course, and no view predicts individual admission.

## Follow-up order

The next source-backed increments are a retained CNOUS restaurant overlay and
commune-coded rent references with editable assumptions. Course/career links
first need the Onisep correspondence; outcomes should begin as source-native
InserSup/InserJeunes exploration before any admissions attachment. Travel routing,
student mobility and education-desert measures require their own populations and
geographic contracts. Revision comparison needs an explicit release-to-release
identity strategy. These are future work, not hidden parts of this delivery.
